Session Routing Lab

Four users visit a site behind a load balancer. Their first request logs them in and creates a session. Where that session is stored decides what happens when servers are busy, added, or crash.

How to use:
  1. Click a User button. Their first request logs them in; later requests need that session.
  2. Choose the design: Stateful keeps sessions inside each server. Stateless keeps them in a shared store.
  3. Change how the load balancer routes (Round robin or Sticky), crash servers from their cards, add servers, or start a traffic spike.
  4. Follow the Missions on the right. The log explains every request in plain words.
