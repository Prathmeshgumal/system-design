Stateless Tier Self-Check

Ten questions, phrased the way an interviewer might ask them. Pick an answer to see why it is right or wrong. Any question you miss is a good one to bring to our doubt session.

Score 0 / 10

Say it in an interview, in about 60 seconds

  1. To scale the web tier horizontally, any server must be able to handle any request.
  2. So I keep web servers stateless: no session data in their memory.
  3. Sessions go in a shared store that every server reads. The book uses NoSQL because it scales easily; Redis is also common.
  4. That removes the need for sticky sessions. A server crash logs nobody out, and adding servers helps everyone immediately.
  5. It makes autoscaling easy: add web servers under load, remove them when traffic drops.
  6. The cost is an extra lookup per request, and the session store must be fast and replicated so it is not a single point of failure.
