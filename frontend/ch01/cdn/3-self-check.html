Chapter 1 · CDN · Self-check

CDN Self-Check

Twelve questions, phrased the way an interviewer might ask them. Pick an answer to see why it is right or wrong. Any question you miss is a good one to bring to our doubt session.

Score 0 / 12

Say it in an interview, in about 60 seconds

  1. Static files like images, CSS, JS and video should not be served by our web servers. We put them on a CDN.
  2. A CDN is many cache servers spread around the world. A user gets the file from the nearest one, so it loads fast.
  3. On a miss, the edge fetches the file from our origin (web server or S3), caches it for the TTL the origin sets, and returns it. Later users near that edge get a hit.
  4. Trade-offs: we pay per GB transferred, so we skip rarely used files. We pick a TTL that is neither too long (stale) nor too short (origin load).
  5. To push a change early we invalidate through the vendor API or, better, version the URL like app.js?v=2.
  6. If the CDN goes down, clients fall back to the origin.
